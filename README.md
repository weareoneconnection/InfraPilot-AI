# InfraPilot AI

**交通基础设施现场感知与闭环整改系统**

InfraPilot AI 面向铁路、公路、桥梁、隧道、港口和机场的施工现场：一线人员用一句话和一张照片上报问题，系统把它定位到具体构件，判断风险并设定响应与关闭时限，由专家智能体给出有依据的处置，经具名人员批准后派发整改任务；整改完成后，必须由**未参与整改的人**提交**新的、在现场、在派发之后拍摄**的照片，独立复检通过才能关闭。关闭的事件沉淀为同一构件、同类隐患的先例。

> 本项目作为独立参赛应用交付，可单独部署、运行、评测和复现；事件、证据、复检回执与项目指标可通过 REST API 输出，MCP 仅开放受控的上报与查询能力。

## 阶段 11 现场智能操作系统

当前界面不再是单一工单页，而是由七个互相联动的工作区组成：

1. **现场指挥中心**：项目 KPI、风险分布、空间态势、九步闭环和最近活动。
2. **智能巡检上报**：手机相机、文字/语音、GPS/EXIF、二维码和四类黄金演示场景。
3. **风险事件中心**：风险融合、证据路由的专业研判、具名审批、整改任务和审计轨迹。
4. **空间数字孪生**：项目、区域、构件、电子围栏与事件热点，可继续接入 GeoJSON、IFC、GLTF 和 3D Tiles。
5. **独立复检中心**：整改前后证据对比、照片哈希、时间、位置、人员独立性和七项关闭条件。
6. **项目分析驾驶舱**：SLA、关闭率、资产覆盖、区域压力、构件热点和智能体参与度。
7. **智能体协同目录**：3 个控制智能体与 4 个专业智能体的职责、边界和人工闸门。

`GET /workspace` 提供项目、智能体、生命周期、复检契约和演示场景元数据；`GET /events/{event_id}/evidence` 生成带 SHA-256 摘要的可移交证据快照。

## 解决什么问题

| 现场常见问题 | InfraPilot AI 的做法 |
| --- | --- |
| 上报说不清在哪里 | 文本中的构件号、扫码 `asset:P47`、手机定位、照片 EXIF 定位，自动对应到登记的构件 |
| 风险被低报 | 最终风险取上报人、文字信号、图像识别三者最高值，**只升不降**；高风险自动停工提示 |
| 整改拖延没人管 | 风险决定响应和关闭时限（紧急 1/24 小时、高 4/72 小时、中 24/168 小时、低 72/336 小时），超期自动标记 |
| 处置建议没有依据 | 专家按事件检索到的受控依据路由，结论必须引用来源，没有依据就说明缺口并提问 |
| “已整改”只是一句话 | 复检须提交新照片：哈希与感知哈希均不同于整改前照片，拍摄时间晚于派发，GPS 在构件范围内（或复检人到场确认），复检人未参与整改，全部任务已完成 |
| 同样的问题反复出现 | 已关闭事件按构件和隐患信号自动成为先例，显示当时的措施和关闭用时；看板统计隐患热点 |

## 运行

```bash
git clone https://github.com/weareoneconnection/InfraPilot-AI.git && cd InfraPilot-AI
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
./run.sh                    # http://127.0.0.1:8101
pytest -q                   # 41 项测试
python evals/run_eval.py    # 34 项基准
```

MCP（官方 MCP Python SDK v2）：巡检机器人、无人机或其他智能体可以上报观察、读取事件和看板；审批、派发、复检和关闭不通过 MCP 暴露。

```bash
python -m app.mcp_server                               # stdio
python -m app.mcp_server --transport streamable-http   # http://127.0.0.1:8111/mcp
```

界面上的“生成演示照片”会合成带拍摄时间和 GPS 的示例照片（不是真实现场照片），方便没有现场照片时演示完整闭环；“复用整改前照片”可以演示复检拦截。手机浏览器中的“选择文件”可以直接调用相机。

## 闭环

```text
感知（文字 / 照片 / 定位 / 扫码）→ 定位构件 → 风险融合（只升不降）→ 时限与停工
 → 证据路由的专家研判 → 具名人员批准 → 派发任务（责任角色 + 截止时间）
 → 责任人完成整改 → 独立复检（7 项核验）→ 关闭 → 沉淀为先例
```

复检核验的 7 项检查：全部任务已完成；有整改后照片；不是整改前照片的复用或翻拍（SHA-256 + 512 位行列差分感知哈希）；拍摄时间在派发之后（EXIF，含时区偏移）；拍摄位置在构件电子围栏内（或复检人到场确认，回执中注明依据）；复检人未参与整改且不是上报人；隐患已消除（配置视觉模型时由模型复核）。

## 可选的视觉模型

设置 `INFRAPILOT_MODEL_BASE_URL`、`INFRAPILOT_MODEL`（以及 `INFRAPILOT_MODEL_API_KEY`）后，可接入 OpenAI 兼容的视觉模型（如通义千问 VL、本地多模态模型）。模型只能从 10 类隐患分类中选择、置信度不低于 0.5 且须说明可见依据，否则丢弃；模型结果只能**提高**风险，复检时若仍识别出隐患则复检不通过。未配置时使用确定性的文字规则，不宣称具备图像识别能力。

## 边界

构件坐标、知识来源和照片均为合成内容。EXIF 可以被篡改，生产中应结合设备认证、水印或可信拍摄应用；离线上报队列、对象存储、身份认证和消息推送属于部署集成内容。参考实现不会向任何外部系统发送指令或消息，派发只生成内部任务与回执。
